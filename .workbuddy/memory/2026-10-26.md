## Docker 部署改造（已完成并验证）

**架构决策**：复用宿主机已运行的 `novel-mysql`(3307) / `novel-redis`(6379) 容器，只容器化三个 Java 服务。
理由：`doc/sql/novel_plus.sql` 只有 156KB **纯表结构，不含任何小说数据**；现有库里有真实抓取的 244 本书 / 2268 章 / 11360 条目录。改用初始化 SQL 重建 = 数据全丢。

**端口**：front 8083 / admin 8089 / crawl 8081（原 compose 里 8083:8083、8084:80、8081:8081 三个全错位）。

### 修掉的三个致命坑
1. **Dockerfile 依赖预编译 jar**：原写法 `COPY novel-front.jar`，jar 必须事先手工放进 `src/main/build/docker/`（那个 109MB 作者的 jar 就是干这个的，已被删）→ 改为 `context: ./novel-<module>` + `COPY target/novel-*-*.jar`，直接吃 `mvn package` 产物。
2. **ShardingSphere 配置缺失**：`jdbc:shardingsphere:absolutepath:${user.dir}/config/shardingsphere-jdbc.yml` 要求 jar 同级有 `config/` 目录，原 Dockerfile 只 COPY 了 jar → 启动即失败。改为 `COPY src/main/build/config/ /app/config/`。
3. **驱动覆盖把分片关了**：原 entrypoint 传 `-Dspring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver` + 环境变量 `SPRING_DATASOURCE_URL`，会绕过 ShardingSphere。但 `book_content` 必须走 `book_content0~9` 分表（`index_id % 10`），绕过就查不到正文 → 已删除该覆盖，数据源统一由 `config/shardingsphere-jdbc.yml` 决定。

### 新增/修改文件
- 新增 `novel-{front,admin,crawl}/src/main/build/docker/config/shardingsphere-jdbc.yml`（jdbcUrl 指向 `host.docker.internal:3307`，sql-show 关闭）
- 重写三个 `src/main/build/docker/Dockerfile`（eclipse-temurin:21-jre，JAVA_OPTS 可调，TZ=Asia/Shanghai）
- 重写根 `docker-compose.yml`（仅 3 个应用服务 + `pic-data` 卷 + `extra_hosts: host.docker.internal:host-gateway`）
- 新增三个模块的 `.dockerignore`（`target/*` + `!target/*.jar`）
- 端口改由环境变量 `SERVER_PORT` 统一覆盖（build/config 里 front=8085、admin=8088、crawl=8083 与资源目录不一致）

### Redis 配置键不一致（坑）
- novel-front / novel-crawl 走 `spring.data.redis.*` → 环境变量 `SPRING_DATA_REDIS_*`
- novel-admin 的 `ShiroConfig` 用 `@Value("${spring.redis.host}")` → 环境变量 `SPRING_REDIS_*`
两边都要设，只设一个会导致其中一个连 127.0.0.1 失败。
